This record describes the 3.33 release line at its GA release, `3.33.0`, taken from the first line of `CHANGELOG.md` at this commit. The git tag `v0.33.0` uses a `0.` prefix for tagging purposes only; this SDK publishes under a `3.` prefix. Every release candidate and patch release of 3.33 shares this record.

`3.33.0` follows the release candidate `3.33.0-rc.1` (tag `v0.33.0-rc.1`, 2026-10-05). The GA tag dates 2026-10-16. The comparison below is against `3.32.0` (tag `v0.32.0`), the release the 3.32 record describes, so it covers the full change from one release line to the next.

## SDK shape

The Navigation SDK for Android splits into a public tree (`mapbox-navigation-android/`, released to customers as separate Maven artifacts) and an internal tree (this repository root) that adds proprietary feature modules on top. Core libraries carry route state, native-engine bridging, trip data and, new in this line, the SDK-wide coroutine dispatchers. UI libraries render maps, camera, and turn-by-turn components on top of Core. Optional libraries add EV routing, ADASIS, road camera, weather, audio, MapGPT, Compose wrappers, and the Redux-style coordination layer, each consumed selectively by an integrator. Everything bottoms out on bound Mapbox SDKs: Maps SDK `v11.33.0`, Navigation Native `v324.33.0`, Core Common `v24.33.0`, Nav SDK C++ `v0.33.0` (and its full HD artifact at the same version), Search SDK `v2.33.0`, and Mapbox Java SDK `v7.10.1`, all resolved from `mapbox-navigation-android/gradle/dependencies.gradle` at this commit. `compileSdk` and `targetSdk` are 37, `minSdk` is 21.

Seven modules declare a native SDK directly: `navigator` and `base` in the public tree, and `coordination`, `coordination-full-hd`, `datainputs`, `roadcam`, `libnavigation-compose-core` in the internal tree. Every other library reaches native code through them (see `04_native_bridge.md`).

Since the previous release tag `v0.32.0`, the public tree added one library, `dispatchers`, and renamed the Gradle module `androidauto` to `android-auto-components`. The internal tree's module set is unchanged.

## What changed since the previous release tag

Previous release tag: `v0.32.0` (`3.32.0`, commit `61b7d227ff85c5b2fe03fed6aa5268b6f2211030`).

| Library | Change | Evidence |
|---|---|---|
| (SDK-wide) | Bound Mapbox SDKs moved from their `32.0` releases to `33.0`: Maps SDK `v11.33.0`, Navigation Native `v324.33.0`, Core Common `v24.33.0`, Nav SDK C++ `v0.33.0`, Search SDK `v2.33.0`. Mapbox Java SDK stays at `v7.10.1`. Between `3.33.0-rc.1` and `3.33.0` only the version suffix moved, from `33.0-rc.1` to `33.0`. | `mapbox-navigation-android/gradle/dependencies.gradle` |
| `dispatchers` | New Core library, published as `com.mapbox.navigationcore:dispatchers`. `SdkDispatchers` holds the Default, IO and Main coroutine dispatchers the SDK runs on, and the experimental `SdkDispatchers.configure` with `SdkDispatchersConfig` lets an app replace them or limit their parallelism. It depends on the new `com.mapbox.annotation:annotation` artifact (`0.3.0`) and declares no native SDK. | `mapbox-navigation-android/settings.gradle`, `dispatchers/build.gradle`, `dispatchers/api/current.txt`, `gradle/artifact-settings.gradle` |
| `navigation`, `base`, `utils` | Depend on `dispatchers`: `navigation` through `api`, `base` and `utils` through `implementation`. | `navigation/build.gradle`, `base/build.gradle`, `utils/build.gradle` |
| `navigation` | New experimental EV charging control: `MapboxNavigation#startCharging`, `MapboxNavigation#stopCharging`, `StopChargingCallback` and `ChargingFinishedData`. New experimental `NearestPointOnRoute` with three nearest-point-on-geometry helpers. A restricted `NativeRerouteControllerState` package for library-group use. | `navigation/api/current.txt`, `CHANGELOG.md` |
| `base` | New experimental `ChargingState` and `RouteProgress#chargingState` / `RouteProgress#isChargingExpected`. Primitive-array accessors (`edgesArray`, `alertcCodesArray`, `innerEdgeIdsArray`, `outerEdgeIdsArray`) added beside the `List` accessors, which are deprecated. | `base/api/current.txt`, `CHANGELOG.md` |
| `android-auto-components` | Gradle module renamed from `androidauto`; the Maven artifact name `android-auto-components` is unchanged. New experimental `CarNavigationTemplates` and constructors for `MapboxCarNavigationManager`, `MapboxCarNotification` and `CarSpeedLimitRenderer` that work without `MapboxCarContext`. `CarFeedbackOptions` gained `attachScreenshot`, `bitmapEncodeOptions` and `toBuilder()`. `CarFeedbackPollProvider.getPlaceFeedbackPoll` added; `getSearchFeedbackPoll` and `CarPlaceSearchOptions` deprecated. | `mapbox-navigation-android/settings.gradle`, `android-auto-components/api/current.txt`, `CHANGELOG.md` |
| `coordination` | Public API now tracked: `api/current.txt` goes from absent to a full baseline covering the navigation presenter, its configuration DSL, camera, route line, cutout, location indicator and route object matching packages. Tests use the new `libtesting-dispatchers`. | `coordination/api/current.txt`, `coordination/build.gradle` |
| `datainputs` | New experimental `SteeringData` and an `updateSteeringData` entry point for front-wheel angle input. | `datainputs/api/current.txt` |
| `ev-ui`, `applemusic-mapgpt` | Depend on `dispatchers`. `MapboxEvViewClient` now defaults its IO dispatcher to `SdkDispatchers.IO`. | `ev-ui/build.gradle`, `applemusic-mapgpt/build.gradle`, `ev-ui/api/current.txt` |
| `ev-driver-notification` | Two new file-level Kotlin classes in `api/current.txt` with no members. | `ev-driver-notification/api/current.txt` |
| (all libraries) | Every library `build.gradle` in the internal tree, and the public tree's root `build.gradle`, now applies the shared Detekt static-analysis script. Build tooling only, with no effect on published artifacts. | `build.gradle` of each library, `gradle/dependencies.gradle` |

## Module notes

`dispatchers` is the one new library in this line. It sits in Core below `navigation`, `base` and `utils`, and two optional libraries use it directly. `android-auto-components` changed name at the Gradle level only. `coordination` has a tracked public API for the first time, so later records of this library compare against that baseline. No module record exists for this line.
